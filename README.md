# 旅途筆記

[開啟旅遊行程網站](https://ryan950073.github.io/travel-planner/)

這是供親友一起規畫旅行的網站，可安排每日景點、餐飲、交通與住宿，並查看預算。網站由 GitHub Pages 發布，行程儲存在 Supabase 免費專案。

## 開始使用

1. 在網站填入行程名稱與目的地，加入日期、每日安排、交通住宿及預算。
2. 按「儲存行程」，再按「分享行程」複製完整連結。
3. 親友打開連結後即可查看及編輯同一份行程。編輯後請按「儲存行程」。

**完整分享連結就是編輯憑證。** 持有者都能查看和修改該行程，請只傳給信任的親友。此版本沒有個別帳號或唯讀權限。若兩人同時修改同一版本，後儲存者會看到衝突提示，需重新整理並合併變更。

## 網站維護

- GitHub Pages 從 `main` 分支的 `/docs` 資料夾發布。修改其中檔案後，GitHub 會重新部署網站。
- `docs/config.js` 放的是 Supabase 專案網址與**可公開的 publishable key**；請勿在網站檔案中放入 secret 或 service-role key。
- `supabase/schema.sql` 是資料表與行程存取功能的設定。它已在目前的 Supabase 專案執行；只有重建資料庫時才需要再執行。
- Supabase 免費專案可能因長時間未使用而暫停，屆時可到 Supabase 控制台恢復。
- 先前本機預覽中的示範行程不會自動移入目前資料庫。

## 消費、分帳與匯率

- 切換到「消費與分帳」，先加入自己與旅伴，再按「記一筆消費」。可選擇付款人、部分或全部旅伴、平均分攤或自訂新臺幣金額。
- 每筆消費保留日期、分類、原幣金額、入帳匯率、匯率來源／日期、備註與分攤明細。平均分攤以新臺幣「分」計算，尾差按旅伴順序分配；自訂分攤總額必須精確相等。
- 行程中的費用屬於**預估費用**；帳本是**實際消費**，兩者不會相加而重複計算。實際預算餘額會依旅程的預算計算。
- 「誰該付給誰」顯示以新臺幣結算的還款建議。完成實際付款後，可按「標記已還款」；可撤銷紀錄。這個按鈕不會轉帳。修改或刪除已結清的消費，會重新計算應收、應付或退款。
- 「匯率換算」可換算 14 種常用幣別。自動匯率來自 [Frankfurter 官方 API](https://frankfurter.dev/) 的每日參考資料，畫面顯示資料日期；無法查詢時可手動輸入。參考匯率不含銀行價差與刷卡手續費。
- 消費的匯率在入帳時固定，之後查詢匯率不會改寫既有消費。若需改用實際刷卡匯率，請編輯該筆消費。
- 所有消費、旅伴與還款紀錄都放在同一份行程中，**操作後仍須按「儲存行程」**，親友重新載入完整分享連結即可看見更新。原有版本衝突檢查繼續適用。

### 相容性與驗證

新版沿用現有 Supabase JSONB 行程文件，新增 `members`、`expenses`、`payments` 三個可選陣列。舊行程會以空帳本開啟，不影響每日安排；**不需執行新的 SQL 或遷移資料庫**。既有資料容量上限為 100,000 字元，前端會在接近上限時提示拆分行程。

純計算測試（Node.js 18+）：

```sh
node --test tests/ledger.test.cjs
```

完整瀏覽器測試：安裝 Playwright 與 Chromium，在一個終端啟動 `python -m http.server 8765 --directory docs`，另一個終端執行 `node tests/browser.cjs`。可用 `TEST_URL` 指定測試伺服器、`CHROMIUM_PATH` 指定已安裝的 Chromium。瀏覽器測試攔截資料庫與匯率請求，不會寫入正式行程；涵蓋舊資料載入、消費編輯、分攤、還款、儲存重載、版本衝突、儲存期間修改、匯率失敗／請求競速及手機版面。
